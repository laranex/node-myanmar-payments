# Changelog

All notable changes to `@laranex/myanmar-payments` (node-myanmar-payments) will be documented in this file.

## v4.0.0 - Unreleased

Initial release. The version number matches the other Laranex Myanmar payments packages (`php-myanmar-payments`, `laravel-myanmar-payments`, `go-myanmar-payments`), and the gateways, flows, validation, signing, status maps, results and errors are a port of them, sharing their test vectors.

### Added
- Gateways: KBZ Pay (`pwa`, `qr`, `app`, `status`), Wave Money (`initiate`), AYA Payment Gateway (`services`, `initiate`, `status`, `verifyRedirect`), Yoma MMQR (`initiate`, `renewQr`, `status`, `forgetToken`) and CyberSource Secure Acceptance (`initiate`); every gateway validates its payment data (`KbzPay.validate()` and so on) and verifies callbacks with `handleCallback`.
- Subpath exports per gateway (`@laranex/myanmar-payments/kbz-pay`, `/wave-money`, `/aya-pay`, `/yoma-mmqr`, `/cyber-source`) next to the root export, as ES modules and CommonJS with type declarations.
- Exact `Amount` type (`Amount.kyat()`, `Amount.parse()`) kept as decimal text, so amounts never pass through a float; payment data also takes a whole-number `number` or `bigint` and rejects fractions. Decimals are accepted only where the gateway documents them (KBZ Pay up to 2 places, CyberSource any); every gateway except CyberSource is MMK only.
- A config class per gateway with `fromEnv(process.env)`, reading the same credential, setting and URL variables as the PHP, Laravel and Go packages; a missing setting throws `ConfigurationError`. `MyanmarPayments` builds every gateway lazily from one config object or the environment.
- Every gateway uses its production endpoints; the URL settings are optional overrides, for example to test against UAT.
- Configuration: the HTTP timeout (`timeoutSeconds`, `MYANMAR_PAYMENTS_HTTP_TIMEOUT`) is optional and defaults to `DEFAULT_TIMEOUT_SECONDS` (30). The time to live settings are optional too: KBZ Pay's `timeToLiveMinutes` (`KBZ_PAY_TIME_TO_LIVE_IN_MINUTES`, 1 to 120) and Wave Money's `timeToLiveSeconds` (`WAVE_MONEY_TIME_TO_LIVE_IN_SECONDS`, greater than 0); time settings take a whole number or its text. Every other setting of a gateway you use is required, including Wave Money's `merchantName` and Yoma MMQR's `apiVersion`. A missing setting throws the `ConfigurationError` naming it; a value out of range throws one such as `The kbz_pay configuration [time_to_live_in_minutes] must be a whole number from 1 to 120.`
- Time to live per payment: `KbzPayPaymentData`'s `timeToLiveMinutes` (1 to 120) and `WaveMoneyPaymentData`'s `timeToLiveSeconds` override the configured value; a payment with neither its own nor a configured time to live throws `InvalidPaymentDataError` before any request is sent. `WaveMoneyPaymentData` also takes an optional `merchantName`. CyberSource payments take `currency`, `locale` and `transactionType`.
- Result classes: `RedirectPayment`, `FormPayment` (with `toHtml()`), `QrPayment` (with `qrImageDataUri()`) and `AppPayment`; `PaymentCallback` (with a gateway-independent `PaymentStatus` and the `Acknowledgement` each gateway expects, sent with `send(res)` or `toResponse()`) and `PaymentStatusResult`.
- `CallbackRequest.fromNodeRequest()` (node:http, Express), `CallbackRequest.fromWebRequest()` (Fetch API servers such as Next.js, Hono and Bun), `CallbackRequest.from()` and `CallbackRequest.fromJson()`. JSON numbers in callbacks are read without a float conversion, so signatures and amounts keep the gateway's exact text.
- `CallbackRequest.rawBody` holds the exact bytes received, next to `body` as text. JSON numbers stay exact strings in `raw`, `parsedBody()`, `input()` and `queryInput()` (`1000.50` is `'1000.50'`).
- `Amount.equals()` compares by value, ignoring leading zeros (`'01000'` equals `Amount.kyat(1000)`).
- Errors: `PaymentError` and its subclasses `InvalidPaymentDataError` (per-field `errors`), `ApiError` (`gatewayCode`, `gatewayMessage`, `httpStatus`, `raw`, `cause`), `SignatureVerificationError` and `ConfigurationError`.
- No runtime dependencies: the global `fetch` (or an injected `fetch` / `HttpClient`, the configured `timeoutSeconds`, `AbortSignal` per call) and `node:crypto`; an injectable `TokenCache` with an in-memory default for Yoma's access token.
- CyberSource callbacks trust only the fields listed in `signed_field_names`: `decision` and `req_reference_number` must be signed, and unsigned fields are left out of the result and `raw`.
- Callback hardening: AYA Pay payloads need their order, transaction, amount, currency (104) and status fields well formed and no `:` in a signed value but `dateTime` (and payments reject `:` in `orderId`, `description` and `userRefs`); CyberSource rejects a `signed_field_names` that does not sign itself, repeats or empties a name, and any `decision` outside ACCEPT, REVIEW, DECLINE, ERROR and CANCEL; Wave Money needs a decimal `amount` and ids of letters, digits, `_` and `-` (also enforced on payments); `fromNodeRequest` and `fromWebRequest` read at most 64 KiB (`maxBodyBytes`); `FormPayment.toHtml(nonce)` adds a CSP nonce.
- AYA Pay reads a `payload` whose `+` signs became spaces in an unencoded return query string.
- Callback, return and cancel URLs only need to be valid absolute http or https URLs; there is no HTTPS-only rule (gateways may still require HTTPS in production).
- Behavior is identical to the PHP, Go and Python SDKs, checked by shared vectors: signing (a nested value in a signed field fails verification), AYA's base64 rules, the Yoma MMQR token cache key (`myanmar-payments.yoma-mmqr.token.<sha256 of base URL and client id>`), `FormPayment.toHtml()` and every error message.
- Agent skill in `skills/node-myanmar-payments` so coding agents use the package correctly; install it with `npx skills add laranex/node-myanmar-payments`.
- Requires Node.js 20 or higher.
